# Field types — implementation brief

Hand this file to Gemini Flash. Do one phase per session. Stop when that phase's tests pass. Do not start the next phase.

Run order is `docs/plans/README.md`. Phase 2 needs `record-history.md` phase 1 and `access-rules.md` phase 1. Phase 3 needs `ux-standards.md` phase 1. Phase 5 needs `process-v2.md` phase 2.

A registrar's table needs a status with options that keep their meaning when someone renames `Admitted` to `Offer made`. A review table needs a reviewer who is a person in the directory, so the system can notify them and apply a rule to them. A notes column needs more than one line. A time-to-complete needs a duration. A table needs a button that starts a process on one row.

The engine has twenty field types. They cover text, numbers, dates, simple selects, and computed fields. They do not cover these.

## What exists today

| Fact | Where |
| --- | --- |
| `FieldType` lists text, number, date, select, boolean, relation, checkbox, multi-select, currency, percent, rating, email, phone, url, autonumber, created time, last modified time, lookup, count, rollup, formula | `scaffoldry-engine/src/lib.rs` |
| Select options are `Vec<String>`, and a record stores the string | `FieldSpec.select_options` |
| Renaming an option leaves old records holding the old string | |
| There is no user, long text, duration, or button type | |
| Index values per type are decided in `row-scale.md` phase 2 | `index_value` |

## Decisions already made

| Question | Answer |
| --- | --- |
| How are select values stored? | By option id. A record holds an id. Renaming an option changes its label only. Deleting an option is a flagged data-loss change |
| What is a collaborator field? | One or more people from the directory, stored as addresses. It is validated on write, shown with names, and usable in rules and notifications |
| Is long text rich? | It is plain text with a small Markdown subset, rendered by a renderer that never passes HTML through |
| Time zones | A date is a calendar date. A date-time is an instant, shown in the person's or the institution's time zone |
| What is a button? | A field that, when pressed on a row, runs a manual-trigger process. It stores nothing |

## Out of scope

- Rich text with images and tables.
- Barcode, geolocation, signature, and password fields.
- A field type defined by an app.
- Per-field encryption.

## Rules for every phase

1. Write the failing test first. Run it. Confirm it fails because the behavior is missing. Then write the code.
2. Do not add a dependency.
3. Each new type has, in the same phase: the manifest schema and validator rules, its `index_value` mapping, its grid cell editor and renderer, its CSV and spreadsheet formatting, which formula functions accept it, and what it shows in history.
4. Every cell editor is operable by keyboard and has an accessible name. Use the kit's `FormField`.

## Phase 1 — select options with ids and colors

Change `FieldSpec.select_options` from `Vec<String>` to `Vec<SelectOption { id, label, color, order }>`. `color` is one of a fixed set: `neutral`, `ok`, `warn`, `bad`, `info`, `accent1`, `accent2`, `accent3`. The tones match `StatusBadge`. A record stores option ids. `id` is generated by the server and never changes.

Migration of existing data. A job, `convert_select_options`, runs once per app when its manifest is first loaded after this phase: assign each string an id, rewrite every record's value from the string to the id, and write the old value into history as a `system` batch. A value that matches no option is kept as a blank and counted in the job result. The manifest keeps accepting the old string list on read for one release and rewrites it.

Rules. A proposal that removes an option raises `data_loss` with the count of records using it. Renaming changes the label only and is not flagged. A write with an unknown id is `400` naming the field. The validator requires unique ids and unique labels per field.

`index_value`: `Select` indexes the id as text, `MultiSelect` indexes one row per id. The kanban and group-by views group by id and show labels and colors.

Tests.

1. Renaming `Admitted` to `Offer made` changes the label everywhere and leaves records unchanged.
2. Removing an option in use is flagged and shows the count. Removing an unused one is not.
3. Conversion: 1,000 records with string values become ids, with none lost, and history holds each old string. A value matching no option becomes blank and is counted.
4. A write with an id that is not an option is `400`.
5. A kanban over a select field groups by id and shows the current label and color.
6. A multi-select with three values makes three index rows and filters by any.

## Phase 2 — collaborator, created by, last modified by

Add `FieldType::Collaborator { allow_multiple }`, `CreatedBy`, and `LastModifiedBy`.

`Collaborator` stores addresses. A write validates each address against the directory, rejects one that does not resolve, and rejects one on hold or inactive with a message that names it. Display always resolves to the person's name with their address, and a person later deactivated shows as `Dr. Rivera (no longer active)`. The field is indexable. `access-rules.md` can compare it to the signed-in person.

`CreatedBy` is set at creation to the actor and never changes. `LastModifiedBy` is set on every user write. Both are computed from the history actor, are read-only, and are shown as names. An automation, an import, and a sync show as `Automation`, `Import`, and `Sync` with the job or rule name in the detail.

Notification hooks. A collaborator field may be marked `notify_on_assign`, which sends the person a notification (`notifications.md` phase 4) when added to a record.

Tests.

1. A write with an unknown address is `400`. A held user is refused and named.
2. A deactivated person renders with `(no longer active)`.
3. `CreatedBy` does not change on update. `LastModifiedBy` does.
4. An import sets `CreatedBy` to the importer and the kind to `Import`.
5. A filter by a collaborator uses the index, with no sequential scan.
6. Web: the picker searches the directory by name, only returns people with read access to the app, and is keyboard operable.

## Phase 3 — long text

`FieldType::LongText`: up to 100,000 characters. Plain text. A small Markdown subset is rendered: paragraphs, line breaks, bold, italic, links, bulleted and numbered lists, and inline code. Headings and block quotes are not part of it.

The renderer is hand-written in `apps/web/src/ui/Markdown.tsx`, under 200 lines. It parses the subset and builds React elements. It never sets inner HTML. A link is made only for `http`, `https`, and `mailto` addresses, opens with `rel="noopener noreferrer"`, and shows its target in the accessible name. Text that looks like anything else is shown as text.

The grid shows the first line, truncated. The drawer shows the rendered text and, in edit mode, a multi-line text area with a character count and a short syntax help. Full-text search includes the field (`row-scale.md` phase 5). It is not indexable for sort or filter and the validator says so.

Tests.

1. A cross-site scripting corpus of at least 30 inputs, including script tags, event handlers, `javascript:` links, data URLs, and nested markup, renders as inert text or a safe element and produces no `script`, `on*` attribute, or unsafe `href` in the DOM.
2. A 100,001-character value is `400`.
3. The subset renders as expected: bold, italic, links, lists, inline code, and a blank line between paragraphs.
4. A link to `javascript:alert(1)` renders as text.
5. The text area has an accessible name and a live character count.
6. Search finds a word inside a long text field.

## Phase 4 — duration and date-time

`Duration { format }`: stored as whole seconds in a number. Formats: `h:mm`, `h:mm:ss`, `d h`, `days`. Input accepts `1:30`, `90m`, `1.5h`, `2d`, and shows the interpretation before commit. Rollups can sum durations. It indexes as a number.

`DateTime`: stored as a UTC instant. Display and input use `platform.timezone` (from `calc-graph.md` phase 4) unless a person sets their own time zone in their settings, a new field in the user settings pane. `Date` remains a calendar date with no time zone. Conversions between the two use the institution's time zone and are explicit in formulas: `TODATE`, `TODATETIME`, added to the function set.

Tests.

1. Input `90m`, `1.5h`, and `1:30` all store 5,400. Output formats render correctly. A bad input shows a message and does not commit.
2. A sum rollup over durations is correct.
3. A date-time entered at 23:30 in a zone is stored as the right instant and displayed at 23:30 in that zone and at another time in another.
4. A `Date` field never shifts across a time zone change.
5. `TODATE` and `TODATETIME` agree with the institution's time zone across a daylight saving change.

## Phase 5 — button

`FieldType::Button { label, rule_id }`. It stores nothing. The grid and drawer show a button with the label. Pressing it calls `POST /apps/{slug}/records/{id}/buttons/{field}`, which checks that the person has the Cedar action `run_automation` on the record, that the record satisfies the rule's `when` conditions, and then starts the rule's instance with trigger `Manual` (`process-v2.md` phase 2). The response is the instance id. A press that the rule's conditions do not meet is `409` with the conditions in words. A button the person may not press is shown disabled with the reason.

The validator requires that `rule_id` exists, belongs to the app, and has a `Manual` trigger.

Tests.

1. Pressing a button starts one instance for that record and returns its id. Pressing again while it is `Waiting` does not start a second.
2. A person without `run_automation` sees it disabled with a reason, and the route is `403`.
3. A record that fails the rule's conditions is `409` with the reason.
4. The validator refuses a button whose rule does not exist or is not manual.
5. Every press is in history as an `automation` batch of the resulting changes.

## Enterprise objections

| Objection | Answer |
| --- | --- |
| Converting existing selects will lose data. | The conversion keeps every matching value, blanks and counts the rest, and writes the old value into history. |
| Long text will carry scripts. | The renderer never sets inner HTML, and a 30-input corpus is a test. |
| A person field will point at people who have left. | It resolves live. It shows `(no longer active)`, and a write cannot add someone inactive. |
| A button will run a process without authority. | It checks the same action as any automation and the rule's own conditions, and every press is in history. |
| Time zones will shift dates. | A date has no time zone. A date-time is an instant shown in a stated zone. |
